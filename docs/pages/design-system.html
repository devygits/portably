How it works

The design system

Every Portably project keeps its design in one file, tokens/tokens.json, and every design value in its CSS comes from it.

One file for the design

tokens/tokens.json holds the design's decisions as named values, called tokens: colours, fonts, sizes, weights, line heights, letter spacing, spacing, radii, shadows, content widths and the shape of the button. check turns it into tokens/tokens.css, plain CSS custom properties the stylesheets use:

.pricing-card {
  padding: var(--pbly-space-6);
  border-radius: var(--pbly-radius-lg);
  background: var(--pbly-color-surface-raised);
}

Change a token and every use follows. Colours are written the way designers copy them: #2F6B4F, rgb(), hsl() or oklch().

Always complete

Every project starts from a complete default system and keeps it complete: colour roles with a hover state, a type scale, spacing, radii, shadows, layout widths and the button. The agent replaces the defaults with the design's values. Where the design says nothing, the default stays, so the next screen always has a value to reach for.

Colours come in two layers. The palette holds the design's colours (color.palette.green); roles say what a colour is for (color.text.muted, color.action.primary, color.surface.raised) and point at the palette. Stylesheets use roles, so a new theme only moves the roles.

Four ways to decide a value

Every hand-written value in project CSS or inline styles is decided in one of four ways:

It exists: use the token

padding: var(--pbly-space-6). fix rewrites values typed by hand.

It's almost the same: snap it

A 15px gap next to 16px steps is a slip. fix snaps it and records the change.

It's deliberate, once: log it

A one-off keeps its value with /* exception: reason */ at the end of the line.

It keeps coming back: promote it

A value used on purpose in two or more places becomes a token, and every use follows.

.hero { padding-block: 5rem; /* exception: hero spacing from the design */ }

What counts as almost the same

ValueSnaps to a token when within
Spacing and radius2px
Font size1px
Line height0.05
Coloura difference most people can't see (ΔE 2.3)
Shadow1px in each offset and blur, with a matching colour

Values smaller than the smallest step are never snapped. Every snap is recorded under "normalizations" in portably.config.json.

Growing the system

When a value outside the system is used in two or more places, check reports it once, with the command that adds it:

python portably.py promote site spacing 80px
python portably.py promote site radius 20px --as radius.xl
python portably.py promote site colour "#E11D48" --as color.palette.rose

promote adds the token, uses it everywhere the value appears and removes exception comments that are no longer needed. It is the only way Portably changes a design system, and it runs only when asked. A new spacing step is named after its size: 80px ÷ 4 is space.20.

Sizes that scale with the screen

A size that grows with the screen goes between two tokens and needs no exception:

.hero__title { font-size: clamp(var(--pbly-font-size-2xl), 6vw, var(--pbly-font-size-5xl)); }

A see-through colour mixes a token: color-mix(in srgb, var(--pbly-color-palette-white) 80%, transparent).

Readable by default

check tests every colour pair the roles promise (text on the page, text on cards, white on the button) and, in a browser, every piece of text against what is really behind it on screen. When a design colour is too faint, it suggests the closest shade that passes. The change is recorded under "readability", for example:

"readability": ["color.palette.green #00915E → #008855: white button text needs 4.5:1"]
