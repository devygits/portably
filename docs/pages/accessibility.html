Accessibility

Accessibility is part of how every component is built, not a final audit step.

The minimum

  • Semantic HTML before ARIA: real buttons for actions, real links for navigation, labelled fields, a sensible heading order.
  • Visible keyboard focus, and motion that respects reduced-motion settings.
  • No fixed pixel root font size, so text follows the reader's preferences.
  • Contrast of 4.5:1 for normal text and 3:1 for large text, field borders and buttons.
  • Colour is never the only carrier of meaning.
  • Alt text on every image, or an empty alt="" when it is purely decorative.

What the check tests

check tests the colour roles in tokens.json, and every piece of rendered text against what is behind it at 390px and 1440px. It reports missing alt text and elements that act as buttons without being buttons. It measures the text in every theme the project defines, such as a dark mode. Hover and focus states aren't rendered, so check those by hand.

Not a certificate

The checks don't certify WCAG conformance. They catch the common failures early; a review with a keyboard and a screen reader is still worth doing.

Every interactive component

  • Uses the right native element, and has an accessible name.
  • Works with the keyboard, in a sensible focus order, without unexpected focus jumps.
  • Defines hover, focus, active and disabled states where they apply.
  • Keeps ARIA state, such as aria-expanded, in step with what happens.
  • Is tested at high zoom and on a narrow screen.

The button

pbly-btn with pbly-btn--primary or pbly-btn--secondary is the only styled shared component. Use <button type="button"> for actions; a link styled as a button stays a link with a real href. Disabled buttons use disabled, and icon-only buttons need an accessible name.
