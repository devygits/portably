What you get

A Portably project explains itself. The decisions survive the conversation that produced them.

The handoff files

FileWhat it tells the next person
README.mdWhat was built: the pages and states, files loaded from other websites, known gaps.
AGENTS.mdHow to work on the project: where things go, the rules, how to record decisions and check. Written for agents and people alike.
DESIGN-SYSTEM.mdGenerated: where the design came from, what was assumed and changed, every token, and which stylesheet styles which page.
DESIGN-SYSTEM.htmlGenerated: the same design system drawn with the project's own tokens, in each of its themes, to look at in a browser.
portably.config.jsonThe Portably version, the namespace, the design source and every decision the code can't show.

DESIGN-SYSTEM.md

check rewrites it every time, so it's never out of date. It opens with where the design came from, the assumptions and the deviations, then lists what the project changed from Portably's defaults and what it added, with each token's description. After the colours, type, spacing, radii, shadows, button and layout, it lists snapped values, colours changed for readability and every deliberate exception with its file and line.

It also maps the project: each stylesheet in css/components/ and css/pages/, the classes it styles and the pages that use them.

See a real one

This documentation site is itself a Portably project. Its design system page is generated by check like any other project's: the colour roles and palette with the contrast of each pair, text styles, spacing, radii, shadows, the button and the layout, drawn with the site's own tokens.
