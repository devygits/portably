Configuration

A project has two files of its own settings: portably.config.json for its context and decisions, tokens.json for its design system.

portably.config.json

KeyWhat it holds
"portably"The Portably version the project was built with. check mentions a different major version.
"namespace"The prefix for Portably's classes and custom properties. Chosen once, at init.
"source"Where the design came from (a Figma file and its frames, screenshots, a URL, a brief) and when.
"assumptions"Decisions made where the source was silent or unclear.
"deviations"Deliberate differences from the source: substitutions, simplifications, requested changes.
"normalizations"Values snapped to a token. fix records its own.
"readability"Design colours changed to pass contrast.
"breakpoints"Extra breakpoints added with promote, such as {"wideMaxPx": 1200}.

"source" is one sentence; the four lists are lists of sentences. DESIGN-SYSTEM.md shows them all.

tokens.json

A documented subset of the design-tokens (DTCG) format: nested groups of tokens, each with a $type and a $value, and an optional $description that DESIGN-SYSTEM.md shows.

{
  "color": {
    "palette": {
      "green": {"$type": "color", "$value": "#2F6B4F"}
    },
    "action": {
      "primary": {"$type": "color", "$value": "{color.palette.green}"}
    }
  },
  "radius": {
    "card": {"$type": "dimension", "$value": {"value": 12, "unit": "px"},
             "$description": "Cards and panels."}
  }
}
  • Types: color, dimension, fontFamily, fontWeight, number, shadow and typography.
  • Dimensions in px and rem, and em for letter spacing.
  • A token can point at another with {color.palette.green}.
  • Not supported: gradients, several shadows in one token, and modes inside the file. Themes are CSS overrides; see Theming.

Required tokens

GroupTokens
Colour rolescolor.background, color.text.primary, color.text.muted, color.action.primary, color.action.hover, color.action.on-primary, color.surface.raised, color.border.default, color.border.strong
Typefont.family.body, the font.size scale from xs to 5xl, four weights, and the text styles text.heading.lg, text.heading.md, text.body.md, text.body.lg, text.label.sm
SpacingThe baseline steps, from space.0 to space.16, at their baseline values
Radius and shadowsradius.none, radius.sm, radius.md, radius.lg, radius.full; shadow.sm, shadow.md, shadow.lg
Buttonbutton.radius, button.padding-block, button.padding-inline, button.min-height, button.font-weight
Layoutlayout.wrapper.max, layout.wrapper.narrow, layout.wrapper.gutter, layout.section.padding, layout.sidebar.width, layout.measure.normal, layout.measure.wide

A project may change any value and add tokens. Tokens it adds must be used.

Breakpoints

The default breakpoints are 980px and 640px, written as @media (max-width: 61.25rem) and @media (max-width: 40rem). Layouts follow the content first, with Grid, Flexbox, minmax() and clamp(), and use breakpoints only where the content needs them.
