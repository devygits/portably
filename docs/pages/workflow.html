How it works

The workflow

The agent follows the same eight steps for every design. They are written for agents in Portably's AGENTS.md; this page explains them for people.

The eight steps

  1. Inspect

    Read the source and anything already built: pages and states, shared values, recurring concepts, responsive behaviour, interactions, assets and content.

  2. Create or open the project

    A new project starts with init. An existing one starts with its AGENTS.md, README.md and DESIGN-SYSTEM.md.

  3. Read the project's guide

    Every project carries its own AGENTS.md: where things go, the value rules, the page anatomy and naming.

  4. Record the source

    "source" in portably.config.json says where the design came from and when.

  5. Tokens first

    The design's decisions go into tokens/tokens.json before any page CSS is written.

  6. Build the pages

    On the shared page anatomy, reusing the project's components and conventions.

  7. Check as you go

    check --json for the findings, fix for the safe changes, then every decision is made explicitly.

  8. Record and hand over

    Decisions the code can't show go into portably.config.json, and the work ends with check --strict passing.

Build only what the design contains

The agent builds the pages and states the source shows, or the user asks for, and nothing else. It never adds pages to demonstrate reuse, and it doesn't redesign, simplify or "improve" the design unless asked.

It does normalise small inconsistencies: a 15px gap among 16px gaps, two caption sizes one pixel apart, a colour one shade off the brand colour. The source may be inconsistent; the implementation may not.

When the source is silent

A screenshot has no hover states, a desktop frame has no phone layout, and a brief has no colours at all. The agent makes the smallest reasonable decision and records it under "assumptions". Where an asset is missing (an image, a font, an icon) it uses the closest substitute and records it under "deviations".

Where the design says nothing about a value, Portably's defaults keep the system complete.

Converting existing code

When the source is an existing site, the agent ports what it looks like and does, not how it was written. Utility classes such as mt-5 or text-muted become names for what each element is. The source's CSS variables become tokens. Its framework, build step and dependencies stay behind unless you ask to keep them.

What done means

  • semantic HTML for every requested page and state;
  • CSS in the right files, every design value from a token or a logged exception;
  • JavaScript for the interactions the source shows;
  • local assets with understandable names;
  • the source, assumptions and deviations recorded;
  • a README with the pages, remote dependencies and known gaps;
  • check --strict passing, run last.
